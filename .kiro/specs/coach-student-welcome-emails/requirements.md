# Requirements Document

## Introduction

This feature adds welcome emails for assistant coaches and students when they are created/enrolled in the ShuttleCoach platform. The emails provide credentials, a password reset link for onboarding, and role-specific guidance. The implementation extends the existing branded email infrastructure (`welcomeEmailService.ts`) to support coach and student recipient types while maintaining the LoveAll visual identity (dark header, lime green #B8E135 CTA).

## Glossary

- **Welcome_Email_Service**: The backend service responsible for rendering and sending branded welcome emails via SMTP (nodemailer)
- **Coach_Controller**: The `POST /api/coaches` endpoint that creates new assistant coach accounts
- **Student_Controller**: The `POST /api/students` endpoint that enrolls new students
- **Reset_Token**: A cryptographically random token generated by `generateResetToken()` and stored as a hash in the `password_reset_tokens` table, used to allow first-time password setting
- **Email_Renderer**: The function that generates branded HTML email content following the LoveAll template style
- **Recipient**: The person (assistant coach or student/guardian) receiving the welcome email
- **SMTP_Transporter**: The nodemailer transporter configured with SMTP credentials from environment variables

## Requirements

### Requirement 1: Assistant Coach Welcome Email Trigger

**User Story:** As a head coach, I want newly created assistant coaches to automatically receive a welcome email, so that they can set their password and start using the platform without manual credential sharing.

#### Acceptance Criteria

1. WHEN a new assistant coach is successfully created via `POST /api/coaches`, THE Coach_Controller SHALL generate a Reset_Token for the new coach and trigger the Welcome_Email_Service to send a welcome email to the coach's email address
2. IF the new assistant coach does not have an email address provided, THEN THE Coach_Controller SHALL skip the welcome email without blocking the coach creation response
3. THE Coach_Controller SHALL store the hashed Reset_Token in the `password_reset_tokens` table with a 24-hour expiry before sending the email
4. THE Coach_Controller SHALL send the welcome email asynchronously so that email delivery failures do not block the API response

### Requirement 2: Student Welcome Email Trigger

**User Story:** As a head coach, I want newly enrolled students (or their guardians) to automatically receive a welcome email, so that they are informed of their enrolment and can access the platform.

#### Acceptance Criteria

1. WHEN a new student is successfully created via `POST /api/students` and the student has an email address, THE Student_Controller SHALL trigger the Welcome_Email_Service to send a welcome email to the student's email address
2. IF the student does not have an email address provided, THEN THE Student_Controller SHALL skip the welcome email without blocking the student creation response
3. THE Student_Controller SHALL send the welcome email asynchronously so that email delivery failures do not block the API response
4. WHEN the student is under 18 years old, THE Email_Renderer SHALL address the email to the guardian rather than the student directly

### Requirement 3: Coach Welcome Email Content

**User Story:** As a newly created assistant coach, I want my welcome email to contain my credentials and a password reset link, so that I can onboard and start using the platform.

#### Acceptance Criteria

1. THE Email_Renderer SHALL include the coach's username in the welcome email body
2. THE Email_Renderer SHALL include a password reset link that uses the generated Reset_Token
3. THE Email_Renderer SHALL include the center's login URL
4. THE Email_Renderer SHALL include a brief guide listing what an assistant coach can do on the platform (view assigned students, mark attendance, log training sessions, record assessments)
5. THE Email_Renderer SHALL render the password reset link as a prominent CTA button with the LoveAll lime green (#B8E135) color on a dark (#111827) background section

### Requirement 4: Student Welcome Email Content

**User Story:** As a newly enrolled student (or guardian), I want the welcome email to contain enrolment confirmation and relevant details, so that I know what to expect from the coaching program.

#### Acceptance Criteria

1. THE Email_Renderer SHALL include the student's full name in the welcome email body
2. THE Email_Renderer SHALL include the center name in the welcome email body
3. THE Email_Renderer SHALL include a brief welcome message explaining that the student has been enrolled
4. THE Email_Renderer SHALL include the assigned batch name if a batch was assigned during enrolment
5. THE Email_Renderer SHALL include contact information for the center so the student or guardian can reach out with questions
6. WHEN the student is under 18, THE Email_Renderer SHALL address the greeting to the guardian name provided during enrolment

### Requirement 5: Email Template Branding Consistency

**User Story:** As a platform administrator, I want all welcome emails to follow the same branded template, so that the user experience is consistent across all email communications.

#### Acceptance Criteria

1. THE Email_Renderer SHALL use the same dark header (#111827) with the LoveAll brand mark (lime green #B8E135) as the existing center welcome email
2. THE Email_Renderer SHALL use card-style content sections with light gray (#F9FAFB) backgrounds and border (#E5E7EB) as the existing template
3. THE Email_Renderer SHALL include the standard footer with copyright text matching the existing welcome email
4. THE Email_Renderer SHALL use the same font stack (`-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`) and 600px max-width container as the existing template

### Requirement 6: Email Delivery Resilience

**User Story:** As a system operator, I want the email sending mechanism to be resilient to transient failures, so that temporary SMTP issues do not result in lost welcome emails.

#### Acceptance Criteria

1. IF the initial email send attempt fails, THEN THE Welcome_Email_Service SHALL retry once after a 5-second delay
2. IF the retry also fails, THEN THE Welcome_Email_Service SHALL log the error with the recipient type and identifier and return without throwing an exception
3. THE Welcome_Email_Service SHALL validate the recipient email format before attempting to send, and skip delivery with a warning log if the email is invalid

### Requirement 7: Email Render Function Testability

**User Story:** As a developer, I want the email rendering functions to be independently testable, so that I can verify email content correctness without sending actual emails.

#### Acceptance Criteria

1. THE Email_Renderer SHALL export a pure function `renderCoachWelcomeEmailHtml` that accepts coach-specific parameters and returns an HTML string
2. THE Email_Renderer SHALL export a pure function `renderStudentWelcomeEmailHtml` that accepts student-specific parameters and returns an HTML string
3. FOR ALL valid input parameters, rendering then parsing the HTML output SHALL produce a document containing all provided input values (round-trip content verification)
